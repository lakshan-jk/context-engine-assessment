One /personalize Request — Timeline

POST { userId, question } → { answer, confidence, sourcesUsed }
HTTP boundary ⚡ Instant — pure logic (microseconds) 🐌 Slow — network / LLM I/O
▶

Request arrives + validation EDGE

routes.ts

Fastify validates the body against a JSON schema. Missing/empty/>1000 chars → 400, stop. Engine never runs.

1

Classify intent ⚡ INSTANT

engine/intent.ts

Words → keyword scores → "job" hits career → intent = career. No I/O.

2

Decide what to fetch ⚡ INSTANT

personalization.ts · catalog.ts

career → needed keys → needed services: User, Kundli, Horoscope, Panchang. Only what's needed.

3

Fetch the data — concurrent 🐌 SLOW · I/O

pipeline.ts · gateway/*

All 4 fetches fire at once (not one-by-one). Each one, behind the scenes:

① Check cache — fresh? return instantly, skip network.
② On miss → call service with timeout + retry (2×, backoff+jitter).
③ Each fetch wrapped so failure = a value, not a crash → Promise.all survives.
④ Store result in cache for next time.
4

Build the plan ⚡ INSTANT

engine/personalization.ts

User profile → language (English), tone (motivational), length (350, premium bonus). User failed → safe defaults.

5

Trim to snippets ⚡ INSTANT

engine/catalog.ts

Selected keys → short one-line snippets. Raw payloads thrown away. Failed data → "unresolved".

6

Build prompt + call the LLM 🐌 SLOW · LLM

engine/prompt.ts · llm/*

Focused prompt (rules + question + snippets) → LLM → answer + self-confidence (as JSON).

7

Assemble the response ⚡ INSTANT

pipeline.ts · confidence.ts

confidence = min(coverage, self-assessment, floor). sourcesUsed = resolved keys. Log everything.

◀

Response returned EDGE

200 OK · { answer, confidence, sourcesUsed }. A failed service → degraded answer + lower confidence, never a 500.

The one insight: only steps 3 and 6 are slow — the 4 concurrent (cached, fault-tolerant) fetches and the single LLM call. Everything else is pure, instant computation. So the request is fast, and one slow or failed service can't break it. That's why the scaling bottleneck is the cache and the LLM — not my compute.
